### 环境调整（2026-09-26 22:13）

**决定：放弃 Nix/VM 路线，全部在 Windows + fake bbdev 上完成剩余开发。**

**理由：**
- Nix flake 依赖过大（verilator、chisel、java、python toolchain 等），构建时间和磁盘占用均不划算。
- VM 跑 Linux 也面临同样问题（VM 镜像 + Nix 双重负担）。
- 真实 bbdev 端到端验证可以推迟到：发布前 / 集成测试环境就绪后。

**fake bbdev 方案（核心思路）：**

写一个 `tests/fake_bbdev.sh`（Windows 上是 `.bat`），模拟真实 `bbdev` 行为：

```bash
#!/bin/bash
# tests/fake_bbdev.sh
case "$*" in
  *"--version"*) echo "bbdev version 1.0.0-fake"; exit 0 ;;
  *"verilator"*"--run"*) 
    for i in 25 50 75 100; do
      echo "[Progress: $i%] running..."
      sleep 1
    done
    exit 0 ;;
  *) echo "unknown args: $@" >&2; exit 1 ;;
esac
```

通过环境变量 `BBDEV_BIN` 注入到 `bb-bbdev::detect()`，让 `detect()` 直接返回这个 fake 路径，**跳过所有 fallback 探测**。

**优势：**
- `detect()` 可注入 → 端到端测试可在 Windows 跑
- worker pool / SSE / cancel 全部用 fake bbdev 验证逻辑正确性
- 真实 bbdev 上线时只需切换环境变量
